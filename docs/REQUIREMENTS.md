## 1. 软件整体目标

开发一款 Windows 桌面离线日文翻译应用，能够在没有互联网连接的情况下，对大量日文字幕和文档进行自动翻译。

默认语言方向：

- 输入：日文
- 默认输出：简体中文
- 可选输出：繁体中文
- 可扩展输出：英文

软件至少包含以下能力：

- 批量导入文件

- 自动识别支持的文件类型和文本编码
- 选择翻译模型
- 批量离线翻译
- 翻译质量检测与二次翻译
- 结果预览与人工校对
- 可选输出目录
- 默认输出目录
- 任务进度与错误报告
- Windows 离线启动
- 完整的便携版分发包
- 可选 Windows 安装程序

必须保证软件不依赖外部翻译 API，不需要 OpenAI API Key，不需要用户自己安装 Python。

## 3. 功能一：批量字幕文件翻译

支持用户一次选择多个字幕文件进行翻译。

### 至少支持

- `.srt`
- `.ass`
- `.ssa`
- `.vtt`
- `.lrc`

应实现：

1. 多选添加文件。
2. 直接拖放文件。
3. 文件列表展示文件名称、格式、大小、状态。
4. 支持从任务列表移除文件。
5. 支持清空任务列表。
6. 支持逐文件翻译与批量处理。
7. 翻译完成后自动保存文件。
8. 保留原始文件，不直接覆盖。
9. 单个文件失败不应导致整批任务中断。
10. 提供失败原因及重新处理能力。

### 字幕结构保护

翻译不能破坏原始字幕结构。

必须尽量严格保留：

- 字幕序号
- 起止时间戳
- 字幕顺序
- 字幕条目数
- 字幕格式规范
- ASS/SSA 样式与事件字段
- 字幕定位信息
- 特殊格式控制标记
- 说话人标记和需要保留的非语言内容

翻译时应区分自然语言文本与格式控制信息，禁止将字幕时间轴或 ASS 控制代码直接送入模型翻译。

ASS、SSA、VTT 等格式要单独进行解析、重建和自动化测试，不能简单地通过正则表达式替换整个文件中的文本。

输出字幕必须能够被常见字幕播放器正常读取。

## 4. 功能二：整个文件夹的批量翻译

允许用户选择一个文件夹，对其中所有受支持的字幕和文档进行翻译。

### 输入方式

提供：

- 选择单个文件夹
- 递归扫描子文件夹开关
- 显示扫描到的文件数量
- 文件类型过滤
- 对不支持的文件进行跳过和记录

### 文档支持

第一版至少尝试支持：

- `.txt`
- `.md`
- `.docx`
- `.pdf`（可提取文本的 PDF）

其他格式可根据实现难度扩展。

要求：

1. TXT 保留合理的段落与换行。
2. Markdown 尽可能保留代码块、链接、标题和 Markdown 语法。
3. DOCX 尽可能保留段落、表格和基本格式；不得将整份文档粗暴地转换成纯文本。
4. PDF 主要处理可提取文本的 PDF，允许输出为 DOCX 或 TXT；不要求原版 PDF 排版完全复刻。
5. 对扫描版 PDF，应明确提示无法直接提取文字；如果实现 OCR，必须独立测试其功能。
6. 处理大文档时应分段、分批推理，避免超出模型输入长度。
7. 记录无法处理或存在格式保真限制的文件。

### 输出路径

用户可以设置目标文件夹。

若未选择目标文件夹，则自动保存到用户文档目录下：

`Documents/JapaneseTranslatorOutput/`

实际路径应通过 Windows 系统 API 获取，不能假设用户文档路径固定。

支持以下命名：

- `example.srt` → `example.zh-CN.srt`
- `example.ass` → `example.zh-CN.ass`
- `example.txt` → `example.zh-CN.txt`

对繁体中文、英文使用适当的语言后缀。

批量翻译文件夹时，默认保留原有子目录结构。

处理重名文件时不得静默覆盖；应有明确的冲突处理策略。

扫描目录时必须避免循环遍历输出目录、符号链接导致的死循环以及重复处理新生成的翻译文件。

## 5. 功能三：翻译质量优化与二次翻译

这是本软件的重点功能之一。

普通机器翻译模型经常在日语字幕中产生以下问题：

- 重复翻译语气词
- 日文口语不自然
- 句子不连贯
- 重复词语或短语
- 错误的断句和标点
- 日文原文未被翻译
- 不合理的译文长度
- 前后字幕缺乏语义连贯性
- 人名、专有名词翻译不一致

请设计独立的翻译质量处理模块。

### 5.1 日语语气词处理

重点测试：

- えっ
- あっ
- うん
- ええ
- あの
- その
- そうですね
- はい
- いや
- まあ
- ねえ

这些只是示例，不能把它们简单映射成固定中文。

必须结合实际语言特点，避免出现类似：

`嗯，嗯，嗯，那个，那个，我，我……`

这样的机械重复译文。

但不能一律删除重复。

有些重复是角色紧张、惊讶、犹豫或情绪表达所必需的，必须尽可能保留原意和语气。

### 5.2 质量优化流程

建议设计如下翻译流水线：

原文解析 → 文本清洗 → 语义分段 → 首次翻译 → 异常检测 → 必要时二次翻译 → 安全后处理 → 结构重建 → 输出校验

要求：

1. 初次翻译后检查明显不通顺或重复的候选。
2. 检测连续重复词、重复短语、不合理标点等问题。
3. 检测异常长或异常短的译文。
4. 检测明显残留的日文。
5. 尽可能利用相邻字幕提供的上下文。
6. 对被标记的字幕尝试重新翻译，必要时调整推理参数。
7. 重译后比较候选质量，不能不加判断地用第二次结果覆盖第一次。
8. 对可明确判断的格式性问题进行安全后处理。
9. 对无法自动判断的问题标记为“需要人工检查”。
10. 保留原译与优化译文，支持用户比较。

需要特别注意：M2M100 是机器翻译模型，不是指令式聊天模型，不能假设它能够理解自然语言提示词。

请根据所选模型的真实技术能力实现上下文、重译和质量控制，不得假装模型支持不存在的功能。

### 5.3 可配置优化级别

在 GUI 中提供：

- 标准翻译
- 自动质量优化
- 质量优先（更多重译与检查）

允许用户关闭自动优化。

优化过程必须保持字幕条目与时间轴的对应关系。

不能为了所谓“润色”而编造剧情、添加原文不存在的信息，或大规模删除对白。

### 5.4 翻译结果校对

提供一个简单可靠的校对界面：

- 左侧显示日文原文
- 右侧显示中文译文
- 显示原始序号和时间戳
- 标识质量检查警告
- 支持人工修改翻译
- 支持单条重新翻译
- 保存修改结果到最终文件

不要求第一版成为复杂的专业字幕编辑器，但基本的校对能力必须真实可用。

## 6. 功能四：内置双翻译模型

必须实现至少两档可实际运行的离线翻译模型。

### 6.1 快速翻译模型

优先考察：

`facebook/m2m100_418M`

目标：

- 优先速度
- 优先降低 CPU 与内存消耗
- 适合大量字幕快速翻译
- 适合普通 Windows 电脑

### 6.2 高质量翻译模型

优先考察：

`facebook/m2m100_1.2B`

目标：

- 优先翻译质量
- 使用较大模型容量
- 提供可调节推理参数
- 接受相对较慢的推理速度

正式采用前，必须验证以上模型确实能够进行日文到中文翻译、能在目标运行时下加载、推理结果真实有效，且符合分发许可证。

### 6.3 本地模型部署

优先使用 CTranslate2 进行推理优化。

请研究适合 Windows CPU 的模型转换与量化方法，例如 INT8，并实际测试。

模型应在构建阶段下载、转换与验证。

**最终离线发行包必须包含所有必要的模型权重、分词器和配置文件。**

在已安装的最终版本中：

- 不能要求用户联网下载模型。
- 不能要求配置 Hugging Face 账户。
- 不能依赖远程模型推理。
- 不能从在线 API 获得翻译结果。
- 不能在本地模型缺失时悄悄切换为在线翻译。

必须验证彻底断网后能够正常启动和翻译。

### 6.4 模型选择界面

提供下拉选择：

- 快速模式（小模型）
- 质量模式（大模型）

显示：

- 模型名称
- 模型状态
- 模型大小
- 模型加载状态
- 运行设备
- 大致内存需求（基于实际测试或明确标注为估计）

模型切换时正确释放不再使用的资源，避免两个大模型无必要地长期同时驻留内存。

### 6.5 设备兼容

默认采用 CPU 模式运行。

不要要求用户必须拥有 NVIDIA GPU。

GPU 加速可以作为可选增强，但不能成为正常使用的前提。

对内存不足、CPU 指令集不兼容、模型文件损坏等情况，应提供明确错误提示。

根据本机硬件资源自行决定合适的线程数和推理参数，并允许用户调整。

## 8. 性能优化与异常恢复

批量字幕翻译可能包含数千条甚至数万条字幕。

请实现必要的性能与可靠性设计：

### 推理优化

- 尽可能批量推理。
- 相同原文可在同一翻译配置下复用缓存。
- 避免每条字幕重新加载模型。
- 避免大量重复的磁盘读写。
- 控制分段长度和批次大小。
- 合理控制 CPU 线程。
- 在性能与内存之间提供合理默认值。

翻译缓存需要区分模型、目标语言及影响结果的推理配置，避免错误复用。

### 任务恢复

- 保持任务状态。
- 支持安全取消。
- 尽可能支持文件级断点续做。
- 对中断的文件使用临时文件或检查点机制。
- 完成写入后再原子替换目标输出。
- 不能因程序异常退出而破坏原始字幕。
- 对失败项提供单独重试。

### 编码处理

需要处理常见编码，例如：

- UTF-8
- UTF-8 BOM
- UTF-16
- Shift-JIS
- CP932

对检测不确定的编码提供用户选择能力。

输出默认使用 UTF-8，并按文件格式要求处理 BOM 和换行。

不得出现大量乱码或者因为单个异常字符导致整批任务失败。

### 9.2 翻译质量测试

- 简单陈述句

- 条目数量
